We wrote these down before the surprise-test runs:

  • If the final-answer check finds the bad step (within one step) on most problem runs, checking every step adds little.
  • If catching the T06 leak needs an alarm line that also flags most correct runs, TRACE is not usable.
  • If one single check explains every catch, the other checks are decoration.
  • If runs written by someone outside our team, or real agent logs, behave differently, our result is tuned to our own data.

How TRACE works

1The agent works in steps

It thinks, uses tools, reads their replies, and answers.

2TRACE checks each step as it happens

Step 5 is judged only on steps 1 to 5, so this could run live. Four questions: backed by proof? matches the tools? too sure of itself? breaks a rule?

3The first step over the alarm line is flagged

With the rule that fired, the reason, and what to do next.
